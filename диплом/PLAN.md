# План: Написание дипломной работы

## Context

Пользователь разработал Qt6/QML десктопное приложение **Report Assistant** — инструмент для автоматизированного составления отчётов о программно-аппаратной совместимости оборудования с ЗОСРВ «Нейтрино» (QNX). Нужно написать полноценную дипломную работу по этому проекту, максимально подробно, в формате как в примере диплома (3 главы + введение + заключение + список источников). Код в приложениях пользователь вставит сам. Код-сниппеты в тексте — вставляем там где нужно.

## Тема диплома

**«Разработка программного средства для автоматизации составления отчётов о программно-аппаратной совместимости оборудования с ЗОСРВ «Нейтрино»»**

## Структура и содержание каждого файла

### `00_vvedenie.md` (~6-8 стр.)
- Актуальность: роль ЗОСРВ «Нейтрино» в критических системах РФ, требования ФСТЭК к сертификации, зачем нужны отчёты о совместимости
- Проблема: ручное составление отчётов трудоёмко, подвержено ошибкам, нарушение структуры тегов ломает PDF-генератор
- Цель работы и задачи (7 пунктов)
- Объект и предмет исследования
- Практическая значимость: интеграция с Jenkins-пайплайном генерации PDF, ускорение рабочего процесса технических специалистов
- Структура работы

### `01_glava1.md` (~12-15 стр.)

**1.1 Операционная система реального времени ЗОСРВ «Нейтрино»**
- Понятие ОСРВ, жёсткое/мягкое реальное время
- Микроядерная архитектура, отличие от монолитных ОС
- Применение в критических и встраиваемых системах (промышленность, авиация, ОПК)
- Сертификация и требования к совместимости оборудования

**1.2 Процесс тестирования аппаратной совместимости**
- Этапы: инсталляция ОС → определение устройств (pci -vvv) → поподсистемное тестирование → фиксация результата
- Категории тестируемых подсистем (таблица)
- Markup-формат для Jenkins: теги @page, @group, @dl/@term, @ul, @hint/@caution/@warning — строгая структура

**1.3 Анализ существующих решений**
- Текстовые редакторы, текстовые процессоры, веб-приложения — всё не подходит
- Специализированных инструментов нет → обоснование разработки

**1.4 Формулировка требований к системе**
- Функциональные требования (таблица: ID, описание, приоритет) — 14 ФТ
- Нефункциональные — 5 НФТ
